# 設計

現状、タイトルバーの×はネイティブの`NSWindow.close()`を呼ぶが、画面内の閉じる・Escapeは`orderOut()`後に所有参照を捨てる。ネイティブのcloseに統一し、再利用のためウィンドウを保持する。ホスティングコントローラーの繰り返し生成と管理されない非表示ウィンドウを防ぐ。既存ルートと合わせ、設定は480×620、統計は520×560にする。AppKitのdelegateプロパティは弱参照なので、実行ループ中のアプリデリゲートの寿命を明示的に維持する。

Lazyweb調査：https://www.lazyweb.com/agentic-search/6ce00b30-ef30-44cf-b126-df680c540029（言語設定モーダル）。言語選択と閉じる操作を維持し、外観の再設計は行わない。

テストはAppKitを初期化し、インストール済みアプリとは別のUserDefaultsを使う。両方の閉じ方で同一性、可視性、内容、タイトル更新、ウィンドウ数の上限を検証する。タイマーセッションやカレンダーへの書き込みは行わない。

UI追加要望：既存のコントロールを4区分に抽出し、翻訳対応のセグメントで選択する。ヘッダーはスクロール領域の外に置く。カレンダー設定をDock・メニューバーから分離し、通知設定をタイマー設定へ移す。バインディングと動作を維持する。

実画面で追加不具合を再現：初回のカテゴリ編集が空の追加画面を開く。表示Boolと対象データの別々の状態を廃止し、識別可能なペイロードとsheet(item:)で設定画面とタイマー画面の表示を一体化する。

カテゴリ一覧の上に翻訳対応の＋ボタンを置く。タイマーのメニューと同じCategoryEditorRequest(nil)のシートを使い、入力検証と保存処理を維持する。
